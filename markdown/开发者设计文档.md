## 三、系统层

### combat.py — 战斗计算

所有攻击计算使用**浮点数**，仅在 HP 变更时 `round()` 取整。

```
base_mult = 1 + floor_atk_pct×(floor-1) + elite_kills×1% + boss_kills×boss_atk_pct   (按难度: 4%/5%/6%每层, 9%/12%/15%每头目)
melee_atk  = weapon_atk × base_mult × (1 + armor_melee_pct) × (strength ? 2 : 1)
ranged_atk = weapon_atk × base_mult × (1 + armor_ranged_pct) × (strength ? 2 : 1)
hp = round((100 + (floor-1)×hp_per_floor + elite×hp_per_elite + boss×hp_per_boss) × (1 + armor_hp_pct))
     hp_per_floor=5/8/10, hp_per_elite=2/3/5, hp_per_boss=10/15/20 (按难度)
暴击: 命中时独立判定 (weapon.crit_chance → damage × crit_mult)
```

**连击**：spear combo=3 (攻击3次后冷却)
**过热**：`if ++cnt >= overheat_count: cooldown = overheat_cd; cnt = 0`
**暴击**：`if random() < armor.crit_chance: damage *= armor.crit_mult`
**秒杀**：`if random() < weapon.instakill[type]: monster.hp = 0`（V1.0.5.10: 头目/首领免疫斩杀）
**三重射击**：`if random() < triple_shot_chance: count = 3`

### pathfinding.py — A* 寻路

- 曼哈顿启发式, 4方向邻域
- 路径简化: Bresenham 直线可见性跳过中间节点
- 重算间隔: 追击 0.5s, 徘徊按需
- Fallback: 随机方向移动

### floor_manager.py — V1.0.5 多房间楼层生成 / V1.0.5.6 BOSS楼层架构

- 每个房间为独立的20×15网格（与原版单楼层相同大小）
- `generate_floor(floor_num)` 返回 `FloorLayout`（含多个 `Room`）
- 每个 `Room` 持有独立 `grid`、`portals`、`spawn_pos`
- 出生点房间有2-4个传送门，双向连接战斗房间
- 传送门在墙壁上：左墙/右墙/上墙/下墙，偏移位置对应
- 击败当前房间所有怪物 → 通往下一楼层传送门激活
- 房间内部无障碍物（纯空房间）
- **主题系统**: `get_theme(floor)` → dungeon(1-9) / snow(11-19) / hell(21-29) / boss(10,20,30)
- 固定刷怪表: 1-4(6+2), 5-9(8+3), 11-19(12+4), 21-29(18+6)，乘以难度 spawn_mult
- V1.0.5.10 怪物线性缩放: HP/ATK = 初始 × (1 + 难度倍率 × (floor-1))，难度倍率 12%/15%/18% 按难度；攻击/技能冷却不随楼层缩放
- V1.0.5.10 头目BOSS: ATK/HP = 初始 × 难度BOSS倍率 × (1 + (Floor-1) × 难度倍率/3)；首领HP = 6000 × 难度HP倍率（单次承伤30 / 每秒承伤100，不吃楼层公式）
- V1.0.5.10 技能规则: 任意怪物满血时无法发动技能，触发失败不进入冷却；首领号令召唤强度=29层；起死回生召唤头目同样适用头目楼层公式
- V1.0.5.11 BOSS技能修复:
  - 起死回生仅一次：`_boss_ultimate()` 末尾补 `boss._ultimate_used = True`（原标志只查不设导致无限触发）
  - 首领号令失败规则：新增 `_boss_summon_allowed()` gate——全场存活精英<4 且 普通<6 才发动；失败不召唤、不提示、不播音效，但仍进入冷却
  - 技能提示全量审计：所有技能（除首领被动外）发动时均弹文字提示，统一带"！"（共13处，含首领号令）
  - 头目BOSS层通关一致化：10/20层杀完BOSS后同样弹出金色提示"当前楼层已完成，传送门已开启"，通关音效在金色提示出现时播放
- 主题精英池: 地牢=精英僵尸/精英骷髅, 雪地=冰霜僵尸/流髑, 地狱=除雪地外全部
- 史莱姆上限: ≤1/4总数 (超额替换不删除)
- 地狱陷阱: 可行走格 10% 置为 4 (排除出生点)

**V1.0.5.6 房间类型（RoomType）**: SPAWN / BATTLE / DUNGEON / TREASURE / ENHANCED_BATTLE（增强战斗）/ BOSS_BATTLE（BOSS战）/ SPECIAL_TREASURE（特殊宝藏，Room.unlocked 标记解锁态）

**V1.0.5.6 楼层结构**：
- 普通楼层：出生点房间 + 分支（数量按 `config.BRANCH_COUNTS` 分段等概率取一：1-5层1-2个 / 6-9层1-3个 / 11-19层2-4个 / 21-29层3-4个）；分支逐个按 `DUNGEON_ROOM_CHANCES` 判定副本（受 `DUNGEON_MAX_PER_FLOOR` 每层上限约束），其余为战斗房间，战斗房间按 `TREASURE_ROOM_CHANCE_BATTLE`（10%）连接宝藏室，副本房间按 `TREASURE_ROOM_DUNGEON_CHANCE`（60%）连接宝藏室
- 头目楼层（10/20）：出生点 + 2个增强战斗房间 + 1个BOSS战房间 + 1个特殊宝藏房间，共5房间；出生点固定4个传送门（`BOSS_BRANCH_COUNT`），增强房间仅与出生点单向星型连接（互不连通）
- 首领楼层（30）：出生点 + 3个增强战斗房间 + 1个BOSS战房间，共5房间（无特殊宝藏房间）
- 通关传送门统一放在出生点房间正中央（`_place_floor_portal`，所有楼层一致）
- BOSS楼层的出生点/增强战斗房间按第一层标准刷怪（`spawn_monsters_for_room` 内部将 floor_num 重置为1）
- `spawn_monsters_boss(room, floor_type, floor_num)`：头目楼层随机2名头目BOSS（`HEAD_BOSS_MELEE` + `HEAD_BOSS_RANGED` 各一，错开摆放）；首领楼层固定高塔之主（FINAL_BOSS）

```

```

### BOSS楼层流程与特殊宝藏室 (V1.0.5.6)

```
combat_scene 统一多房间流程（BOSS楼层不再走单房间旧分支）:
- _init_floor: 所有楼层统一 generate_floor + 布局缓存
- _spawn_monsters_for_current_room: 按房间类型分流
    DUNGEON/TREASURE/SPECIAL_TREASURE → 不刷怪
    BOSS_BATTLE（未清） → spawn_monsters_boss + BOSS登场音效
    其他战斗类（未清） → spawn_monsters_for_room
- _update_portals 准入检查（目标房间类型判定）:
    TREASURE      → 当前房间未清空 → "传送门已被封印！"（红字）
    BOSS_BATTLE   → _boss_room_reachable()=False（出生点/增强房间未全清）→ "传送门已被封印！"
    SPECIAL_TREASURE(未解锁) → 无钥匙: "传送门已上锁！"（红字）
                              有钥匙: "按F键解锁"（紫色）→ F键消耗钥匙解锁
    解锁后即为普通传送门（同一套音效与交互机制），解锁当帧 _unlock_block_travel 阻止按住F直接传送
- _is_floor_cleared: 特殊宝藏/宝藏/副本不参与判定；BOSS_BATTLE 参与
- 传送到达战斗类房间（BATTLE/ENHANCED/BOSS_BATTLE）未清时立即刷新怪物
- 钥匙拾取: "获得 藏宝室钥匙！"（金色toast）；解锁: "特殊宝藏房间已解锁！"
- 特殊宝藏室传送门贴图始终为 icon/block/传送门.webp（与其他普通传送门一致）
```

### 换甲百分比机制 (inventory._equip_armor)

```
ratio = 当前生命 / 换甲前总上限
装备新甲后: 当前生命 = round(ratio × 新总上限)  (clamp 0..new_max)
效果: 换甲前后生命值百分比不变
```

## 六、平衡公式

```
玩家 HP  = round((100 + (floor-1)×5/8/10 + elite×2/3/5 + boss×10/15/20) × (1 + armor_hp_pct))   按难度
玩家 ATK = weapon_atk × (1 + 每层4%/5%/6% + 精英×1% + 头目×9%/12%/15%) × (1+护甲加成) × 力量   按难度（暴击命中时判定）
生物 HP/ATK = 初始 × (1 + 难度倍率×(floor-1))   难度倍率: 默认12%/冒险15%/末日18% (仅普通/精英)
头目BOSS HP/ATK = 初始 × 难度BOSS倍率 × (1 + (Floor-1) × 难度倍率/3)
高塔之主: HP = 6000 × 难度HP倍率; 单次承伤≤30, 每秒承伤≤100
伤害减免 = raw_damage × (1 - DR)
```

- **数据定义**: `data/monsters.py` CHEST 常量

## 九、V1.0.5.12 连击&战斗特效（近战连击系统 / 长按连发 / 特效触发扩展）

### 连击系统架构

- **段表常量**（combat_scene.py 模块级）：
  ```python
  COMBO_RESET_SECONDS = 3.0   # 间隔3秒不攻击, 段数自动重置（与连击归零共用计时）
  COMBO_TABLES = {
      # 每段: range(格)/angle(判定角°)/mult(倍率)/fx
      # fx: ("arc", 颜色, 跨度°) 原地弧形剑气 | ("v", 颜色, 张角°) 向前飞行V形剑气
      "sword":  {"interval": 0.2, "final_cd": 0.0, "stages": [75°白弧×2, 1.8格/100°/×1.5 金V120°]},
      "axe":    {"interval": 0.5, "final_cd": 0.0, "stages": [100°白弧×2, 2格/120°/×5/3 金V120°]},
      "spear":  {"interval": 0.1, "final_cd": 2.0, "stages": [2.5格/45°白V45°×2, 3格/60°/×1.5 金V60°]},
      "dagger": {"interval": 0.1, "final_cd": 1.2, "stages": [1格/45°白V45°×4, 1.5格/90°/×2.0 金弧90°]},
  }
  CHAINSAW_FX = ("arc", (255, 200, 0), 90)   # 机械链锯: 每击附加90°金色弧形剑气
  V_SLASH_SPEED = 432.0   # V形剑气飞行速度 px/s; 存活时长 dur = 射程px / 速度
  ```
- **分发**：`_do_melee_attack` 对 `weapon_type in COMBO_TABLES` 且无过热的近战调用 `_do_combo_attack(weapon_type)`；
  三叉戟（`weapon_type == "spear"`）自动沿用矛段表（仅基础伤害不同）；
  机械链锯走过热兜底路径（90°金弧），其他未知类型兜底 120° 白弧
- **`_do_combo_attack(table_key)`**：
  - 段序：`player.melee_stage`（存下一次段数, 1..N, 0 视为 1）→ 出招 → `melee_stage+1` / 最终段归 0
  - 伤害：`player_melee_attack(stage_mult=段倍率, override_range=段范围, fan_angle_deg=段角度, manage_cooldown=False)`
  - 冷却：非最终段 `attack_cooldown = interval`；最终段 `= final_cd`（>0 时，矛2s/匕首1.2s）否则 `interval`
  - 特效：`fx=="v"` 写入 `v_slashes`（携带 `span_deg`/`color`/`dur=range*TILE_SIZE/V_SLASH_SPEED`，沿 facing_angle 飞行）；
    `fx=="arc"` 写入 `slash_effects`（`span_deg`/`color`）
  - 最终段同时 `_trigger_shake_flash()`（屏幕抖动+轻微闪烁）
- **命中处理抽取 `_process_melee_hits(hit_monsters, mult)`**：暴击额外伤害 = 基础×mult×(crit_mult−1)、吸血、命中音效、击杀结算；**暴击时 `_trigger_shake_flash()`**
- **3 秒重置**：update 中 `_melee_last_used_time >= COMBO_RESET_SECONDS` 时 `combo_counter` 与 `melee_stage` 同步归零

### 长按连发（仅近战）

- `MOUSEBUTTONDOWN(button=1)` → `_attack_held = True`（并立即出招一次保持点击响应）；`MOUSEBUTTONUP(button=1)` → False
- update 每帧：`pygame.mouse.get_pressed()[0]` 校验（失焦/松开自动停止）→ 持有近战武器时调用 `_player_attack()`（由段间/最终冷却自然节流）；返回值按既有 victory 流程传播
- 远程为右键单击单发，不接入长按连发
- 暂停/楼层重置倒计时期间 update 早退，不会触发连发

### 特效触发点（`_trigger_shake_flash`：抖 ±5px/0.18s + 白闪 0.12s）

| 触发点 | 位置 |
|--------|------|
| 连击最终段 | `_do_combo_attack`（stage == n 分支） |
| 近战暴击 | `_process_melee_hits`（护甲 crit 命中分支） |
| 远程暴击 | `_update_projectiles`（`proj['crit_triggered']` 消费处） |
| 幻术师之弓多重箭 | `_player_ranged_fire`（`len(projs) > 1`） |
| 杀戮之弩斩杀 | `_update_projectiles`（`weapon.instakill` 且怪物死亡处） |

### 渲染层

- `draw_v_slashes` 参数化：每条剑气可选 `span_deg`（默认60°）/`color`（默认金色 (255,200,0)）/`length`（默认44px）/`dur`；
  V字**开口朝向玩家**（顶点朝飞行方向、两臂向后张开 `back_angle = angle + π`），亮度/线宽随时间衰减
- `draw_slash_effects` 沿用 `span_deg`/`color`/`dur` 参数化（金弧90°即链锯/匕首横扫特效）
- 屏抖/闪烁复用 `CombatScene.draw` 既有实现（临时 Surface 随机偏移 + 白色半透明覆盖层）
