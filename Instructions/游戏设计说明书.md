| 项 | 值 |
|----|-----|
| 语言 | Python 3.11.15（conda 环境 `Game`） |
| 引擎 | Pygame 2.6.1（SDLC 渲染 + pygame.mixer 音频，24 通道） |

& "C:\Users\Dusk_Wind\.conda\envs\Game\python.exe" -m PyInstaller DungeonWarriors.spec --noconfirm

## 二、目录结构与职责

```
Dungeon Warriors/
├── main.py              # Game 类：主循环、场景状态机调度、死亡/复活/胜利/存档编排

├── data/                # 静态数据层：weapons/armor/monsters/consumables/keys（公式化+索引dict）
├── entities/            # 实体层：Player / Monster / Weapon / Armor / Consumable / KeyItem（@dataclass）
├── systems/             # 系统层：combat / floor_manager / inventory / pathfinding / save_system / audio_manager / revive_system
├── scenes/              # 场景层：menu / settings / combat / backpack / reward / death / victory / game_over
├── rendering/           # 渲染层：renderer.py（地图/精灵/HUD/BOSS血条/剑气/字体缓存）+ pixel_style.py
├── music/  sounds/  icon/   # 资源（BGM / 按怪物分目录音效 / 贴图图标）
├── frame/               # 历史版本设计文档（V1.0.1~V1.0.6 各 Part 方案，策划原始依据）
├── Instructions/        # 项目文档（版本更新记录 / 技术参数资料 / 游戏设计说明书 / 游戏指南与新手教程）
├── 项目宪章.md          # 工程规范（Git/命名/空指针约束）
├── build/  dist/        # PyInstaller 中间产物 / 发布 exe
└── DungeonWarriors.spec # 打包配置
```

分层依赖方向：`scenes → systems → entities → data`，`rendering` 被 scenes 调用；`config` 被所有层引用。禁止反向依赖（systems 不得 import scenes）。

## 三、总体架构

### 3.1 场景状态机

`main.Game` 持有 `scene` 字符串与 8 个场景对象引用，主循环 `run()` 为经典的 `tick → events → update → draw`。场景切换通过各场景 `handle_event()/update()` 的**返回值字符串**驱动，由 `_dispatch_event / _dispatch_update / _dispatch_draw` 三级分发函数统一处理：

```
MAIN_MENU ⇄ SETTINGS
MAIN_MENU → COMBAT ⇄ BACKPACK（B 键进入，B/ESC 退出）
COMBAT → DEATH（有生命）→ COMBAT（复活：HP回满+楼层重置）
COMBAT → GAME_OVER（无生命，3 秒后自动回菜单，存档删除）
COMBAT → REWARD（清层）→ COMBAT（下一层）
COMBAT → VICTORY（击杀高塔之主）→ MAIN_MENU（按任意键）
```

- 叠加绘制：backpack / reward / death / victory / game_over 先绘制底层 combat 画面，再叠加半透明遮罩与自身 UI（`_dispatch_draw`）。
- 楼层布局缓存 `Game.floor_layout_cache: dict[int, tuple[FloorLayout, room_cleared]]` 跨场景持久化在 main 层，解决"地图锁定"与继续游戏恢复（V1.0.5.17/18 语义：继续游戏只保留结构重置清怪状态；复活/手动重置整层重 roll）。

### 3.2 横切机制

- **IME 禁用**：启动时 `SDL_IME_INPUT_ENABLED=0` 等环境变量 + `pygame.key.stop_text_input()` + 屏蔽 TEXTEDITING/TEXTINPUT 事件，防止中文输入法拦截 WASD。
- **日志**：`setup_debug_log()` 将 stdout/stderr 重定向到 debug.log（frozen 时在 exe 目录，每次启动覆盖）。
- **资源路径**：一律经 `utils.resource_path()`，兼容开发与打包。
- **数值口径**：全程浮点计算，仅 HP 变更时 `round()` 取整（V1.0.3 P2 决策）；怪物/玩家文档速度到实际位移的换算系数集中在 config。

## 四、数据层设计

### 4.1 实体（entities/，全部 @dataclass）

- **Weapon**：name/weapon_type/category/attack_bonus/tier/cooldown/attack_range + 可选机制字段（combo_count/move_restricted/crit_chance/crit_mult/instakill dict/overheat_count/overheat_cd/triple_shot_chance）。
- **Armor**：name/armor_type/hp_bonus_pct/damage_reduction/tier + 类型加成（crit/melee/ranged/lifesteal/speed）+ 特殊效果（on_kill_invis/invis_cd/invis_dur）。
- **Consumable / KeyItem**：仅 name + item_type。
- **Player**：基础属性 + 成长计数（current_floor/elite_kills/boss_kills/difficulty）+ V1.0.6 `max_hp_mult` + 双武器槽/护甲 + buffs & status_effects（V1.0.5.11 mode 参数：max/refresh/stack）+ 连击状态（combo_counter/melee_stage）+ 运行时坐标。核心方法：`total_max_hp()/base_attack_mult()/total_melee_attack()/total_ranged_attack()/total_speed()/apply_max_hp_penalty()`。
- **Monster**：类型（normal/elite/head_boss/final_boss）+ 属性 + BOSS 专属（phase/summon_timer/dr_ranged/dr_melee/ranged_immune）+ 伤害上限体系（dps_cap/hit_cap/locked/dr_bonus）+ 不可移动实体（immobile/spawn_interval/ambient_timer）+ `skill_cd`（V1.0.5.19 起为 dataclass 默认字段，杜绝运行时创建遗漏）。核心方法：`take_damage()`（减免→单次上限→每秒滚动窗口→锁血）、`check_phase_transition()`（高塔之主 P2<50%/P3<25%）。

### 4.2 静态数据（data/）

- **weapons.py**：列表推导公式化生成（剑2+2T / 斧3+3T / 矛2+2T+combo3 / 匕首2+1T / 弓弩5+3T）+ 6 把 SPECIAL_WEAPONS；导出 `WEAPON_BY_NAME`、`WEAPON_BY_TYPE_TIER`（不含特殊，供奖励/掉落查表）。
- **armor.py**：`ARMOR_TYPES` 加成系数 × `LEVEL_BONUS` 阶梯组合生成 25 件普通 + 4 件特殊；导出 `ARMOR_BY_NAME/ARMOR_BY_TIER`。
- **monsters.py**：普通/精英/雪地精英/头目（V1.0.6.2 基础 HP 1600）/首领字典列表 + 特殊实体（宝箱/试炼刷怪笼）+ 召唤映射与颜色表。
- **keys.py / consumables.py**：钥匙与消耗品定义 + 药水池 `POTION_POOL`。

> 存档反序列化**按名称查表还原**对象，因此 data 中的 `*_BY_NAME` 索引是序列化体系的基石——新增装备必须进入对应索引。

## 五、核心系统实现要点

### 5.1 战斗系统（systems/combat.py 纯计算 + scenes/combat_scene.py 演出与编排）

职责划分：`combat.py` 只做无状态计算；`combat_scene.py` 负责输入、连击段表分发、特效、掉落、技能演出与击杀结算。

- **近战判定**：扇形（单位向量点积 ≥ cos(半角/2)）且距离 ≤ range×TILE_SIZE + TILE_SIZE//3；默认扇形 145°（等价旧 dot<0.3）。入口 `player_melee_attack(player, monsters, *, stage_mult, override_range, fan_angle_deg, manage_cooldown)`——后四个关键字参数为连击系统服务（V1.0.5.12）。
- **连击分发**：`_do_melee_attack` 优先查 `COMBO_TABLES`（weapon_type ∈ sword/axe/spear/dagger 且无过热）→ `_do_combo_attack(table_key)`：按 `player.melee_stage` 推进段序、段间/最终冷却、写 `v_slashes/slash_effects` 特效、最终段 `_trigger_shake_flash()`；三叉戟 weapon_type=="spear" 自动沿用矛表；机械链锯走过热兜底路径（90° 金弧 `CHAINSAW_FX`）；其他兜底 120° 白弧。
- **命中处理**：`_process_melee_hits(hit_monsters, mult)` 统一处理暴击（护甲，额外伤害=基础×mult×(crit_mult−1)）、吸血、命中音效、击杀结算；暴击即触发屏抖闪烁。
- **冷却/过热**：`manage_cooldown` 分支内处理 combo_count / overheat_count；链锯每 2 击 +0.05s（`OVERHEAT_BURST_EVERY/CD`）；过热提示采用**置位/消费一一对应**：`player._overheat_msg` 由近战路径消费、`_ranged_overheat_msg` 由远程路径消费（V1.0.5.14 修复链锯提示永不显示的错位）。
- **远程**：`_player_ranged_fire` 生成 projectiles dict（weapon/damage/坐标/角度/crit_triggered）；逐帧 `_update_projectiles` 命中后走 `combat._update_projectile_hit`：远程免疫（穿透不销毁）→ 斩杀（BOSS 强制 rate=0）→ 武器暴击 → `Monster.take_damage`。
- **伤害入口**：`Monster.take_damage` 统一走 dr_ranged/dr_melee → hit_cap → dps_cap（1 秒滚动窗口）→ locked 锁血。
- **高塔之主技能**：`_boss_barrage`（冰焰弹幕）/`_boss_ultimate`（起死回生，仅一次）/`_boss_summon`（号令，`_boss_summon_allowed` 判定存活精英<4 且普通<6）/被动吸血在 `combat.monster_attack_player`（60% 概率）。
- **长按连发**：`_attack_held` 状态 + `pygame.mouse.get_pressed()` 校验（失焦自动停），update 每帧尝试出招，由冷却自然节流；仅近战。

### 5.2 楼层生成（systems/floor_manager.py）

- **数据结构**：`FloorLayout{rooms, current_room_idx}`；`Room{room_type, grid, portals, spawn_pos, chests, spawner_positions, consumable_positions, equip_positions, unlocked, ...}`；`Portal{side, offset, target_room_idx, target_side, target_offset, is_floor_portal}`。
- **grid 值语义**：0 地板 / 1 墙 / 2 出生点 / 3 特殊标记 / 5 传送门 / 6 试炼刷怪笼（随机墙生成跳过 2/3/5/6）。
- **generate_floor 流程**：按 `BRANCH_COUNTS` 分段取分支数 → 生成出生点+分支房（`_generate_room_grid` 按楼层布置刷怪笼格）→ `_connect_rooms_with_portals`（**单入口规则** V1.0.5.9）→ `_generate_treasure_rooms`（战斗/副本按难度概率挂宝藏室）→ BOSS 楼层走 `_generate_boss_floor`（出生点+增强战斗+BOSS 房+特殊宝藏房，出生点固定 4 分支）→ `_place_floor_portal`（战斗房中央）。
- **怪物生成**：`spawn_monsters_for_room`（分段数量表 × 难度倍率、精英池按主题、史莱姆 ≤1/4 替换制、距出生点>3 格）；`spawn_monsters_boss`（头目公式 + `head_boss_floor_hp_mult` 第 10 层 ×0.75）；`spawn_trial_spawners`（按楼层 1/3/5 笼）；`spawn_chests`；`place_traps`（地狱 10% 可行走格，幂等防重复）。
- **副本房间**：DUNGEON 类型，1-9 层无副本；刷怪笼索敌 1200px、召唤 CD 6s、`immobile` 分支不受"满血不放技能"门控。

### 5.3 怪物 AI（combat_scene._update_monsters + systems/pathfinding.py）

- **索敌**：距离 ≤ detect（循伤索敌期间 ×1.5）；受远程攻击 `set_track_attacker`（未锁定→向来源移动，已锁定→速度 ×1.5 加成 1s）；BOSS 不受循伤影响。
- **移动**：A*（4 向邻域、曼哈顿启发式、传送门=墙）+ Bresenham 直线可见性路径简化；追击重算节流；`_line_clear` 带网格越界防护（越界视为遮挡，V1.0.5.19 教训）。
- **技能**：满血不发（`can_skill = hp < max_hp`，刷怪笼豁免）；精英技能演出分支在 `_update_monsters`（狙击/多重射击/冰弹/闪击/召唤术式等），投射物经 `_fire_monster_projectile/_fire_ice_bomb/_fire_snipe/_fire_multishot`。
- **BOSS 阶段**：`check_phase_transition` 按血量比例切换属性（P2/P3），阶段图标 `BOSS_PHASE_ICONS`。

### 5.4 存档系统（systems/save_system.py）

- save.json（SAVE_VERSION=2）位于项目根 / exe 目录；`scene_state` 支持 combat/reward 两种中途状态（reward 恢复直接重建 RewardScene）。
- **防御式反序列化**（项目宪章空指针约束的落地样板）：逐字段类型校验 + 非法回退默认；`max_hp_mult` 限 (0,1]；装备按名称查 `*_BY_NAME`，查不到丢弃；backpack 补齐 64 格。
- `mark_game_completed()`：通关后仅保留 `{version, game_completed:true}`，`load_game()` 视为无进度。

### 5.5 背包系统（systems/inventory.py + scenes/backpack_scene.py）

- 背包即 `list[Item | None]`（64 槽）；`inventory.py` 提供纯函数（add/remove/find/count/use/destroy）。
- 场景交互：左键拿起/放下（`_held_item/_held_from`）、右键弹出菜单（使用/装备、销毁 或 替换、销毁）、1-5 快捷使用（`_quick_use` 固定映射，带剩余数量着色 toast）。
- 换甲百分比折算在 `_equip_armor`：先记旧比率，换后 `current_hp = round(ratio × new_max)`。
- 消耗品 5 秒同种冷却记录在 `Player._consumable_cooldowns`。

### 5.6 音频系统（systems/audio_manager.py）

- **单例** AudioManager；`_sounds[key][kind] → list[Sound]` 预加载（ambient/hit/death/projectile 等 kind）；`_monster_key()` 做怪物名→key 模糊映射。
- BGM 走 `pygame.mixer.music`（与音效通道隔离）：`FLOOR_BGM_MAP` 值为文件→直接循环、为目录→随机取曲循环；`play_reward_bgm()` 因 music 通道重载播放会**立即打断**当前 BGM，故胜利瞬间以最高优先级接管（V1.0.5.20）。
- 「音乐控制」开关：`set_bgm_enabled` 即时停止；从设置返回菜单用 `ensure_menu_bgm()`（不打断进度）。

### 5.7 渲染系统（rendering/renderer.py + pixel_style.py）

- 字体：font.ttf/otf 缓存工厂（get_font/get_bold_hud_font/get_title_font...）；粗体 HUD 走单独缓存。
- 地图：`_load_map_textures()` 按主题预载贴图，变种概率在 draw 时掷骰；传送门两态（激活/未激活几何渲染）+ 宝藏室封印红字。
- 图标：`MONSTER_ICON_MAP`（怪物→webp 头像）、`BOSS_PHASE_ICONS`（首领三阶段脸）、背包物品图标多级匹配（精确→去后缀→去T标→关键词）。
- 特效：`draw_slash_effects`（弧形，span_deg/color/dur 参数化）与 `draw_v_slashes`（V 形，dur=射程px/432，开口朝向玩家）。
- HUD：左上三行文本（雪地/地狱白字）；`draw_boss_hp_bar`（480/160px 规则、并排/下移布局）；toast 队列按 offset 依次下排。

## 七、编码规范与强制约束（详见《项目宪章.md》）

- **空指针安全（最高优先级）**：禁止对可空对象直接调用方法/访问属性；可空/非空必须显式区分；反序列化结果使用前必须判空；优先返回空集合/空对象而非 None。
- **序列化实体**：必须有无参构造（dataclass 全默认值）；重要字段不得隐式 null；禁止裸泛型/动态弱类型。
- **存量修复义务**：修改旧模块时须同步扫描并修复同文件内的空指针隐患。
- **命名**：文件小写下划线；场景文件 `_scene` 后缀；类 PascalCase；函数/变量 snake_case；常量 UPPER_SNAKE_CASE；私有成员 `_` 前缀。
- **Git**：分支 main/dev/feature/fix/refactor/docs；提交 `<type>(<scope>): <subject>`，type ∈ feat/fix/refactor/perf/docs/style/test/chore，scope ∈ combat/entity/inventory/render/audio/scene/data/save。
- **版本号落点**：`scenes/menu_scene.py` draw() 中的版本字符串 + `config.py` 头注释 + 文档页脚，三处同步升级。

## 八、扩展指南

### 8.1 新增武器
1. 普通武器：`data/weapons.py` 对应公式列表自动生成，无需登记索引（WEAPON_BY_TYPE_TIER 覆盖）。
2. 特殊武器：在 `SPECIAL_WEAPONS` 加条目（机制字段见 4.1），同时：
   - `combat_scene.UNIQUE_WEAPON_NAMES` 加入名称（拾取橙色提示/特殊宝藏判定）；
   - `reward_scene._gen_upgrade` 对应类别特殊池加入名称；
   - 若新增 weapon_type 且希望接入连击，在 `COMBO_TABLES` 加段表。
3. 背包图标：`backpack_scene.ITEM_ICONS` 加映射（否则走颜色+文字兜底）。

### 8.2 新增怪物
1. `data/monsters.py` 加字典（name/hp/atk/range/cd/speed/detect/color/ranged + 技能字段 wither/frost/burn/fireball/combo_hits 等）。
2. `audio_manager`：`_monster_key` 加名称映射、`_load_all` 的 dir_map 加音效目录（目录不存在会静默跳过）。
3. `renderer.MONSTER_ICON_MAP` 加图标映射。
4. 技能演出：`combat_scene._update_monsters` 按名称分支（提示文案自动生成）；召唤类走 `_spawn_slime_child`/`_boss_summon` 同款坐标钳制逻辑（防越界）。

### 8.3 新增难度
`config.DIFFICULTY_MODIFIERS` 加一个 key（label/spawn_mult/hp_scale_per_floor/atk_scale_per_floor/elite_extra_mult/boss_cd_mult/boss_skill_cd_mult/boss_atk_mult/boss_hp_mult/treasure_room_chances/player_* 成长/upgrade_special_chance）→ 设置界面、刷怪、成长、奖励全链路自动生效（界面按钮遍历该 dict）。

### 8.4 新增房间类型

## 十、已知注意事项（历史 BUG 修复沉淀，勿回退）

1. **运行时创建 Monster 必依赖 dataclass 默认值**——`skill_cd` 曾因首领号令路径未初始化导致 AttributeError（V1.0.5.19）；任何新增字段都应给默认值而非依赖调用方赋值。
2. **网格采样必须越界防护**——`pathfinding._line_clear` 越界一律视为遮挡返回 False；召唤/位移生成坐标须钳制在房间内（留 1.5 格 padding）。
3. **current_floor 语义**：`_on_floor_clear` 先 `+1` 再进奖励界面（供存档/下一层）；奖励界面渲染"已通关楼层"用 `cleared_floor = current_floor − 1`（BUG20 教训）。
4. **过热提示置位/消费必须一一对应**（近战 msg 走近战路径，远程 msg 走远程路径，BUG22）。
5. **继续游戏/复活/手动重置对楼层缓存的语义不同**（V1.0.5.17/18）：继续=保留结构重置清怪；复活/重置=整层重 roll。改缓存逻辑前先读 main._continue_game/_revive_player。
6. **房间刷怪守卫**：`room_cleared`（持久化）+ `_room_spawned`（场景内）双标记防重复刷怪；新增房间类型必须两处都接入。
7. **杀戮之弩对 BOSS 斩杀已被 combat.py 强制归零**——data 中 head_boss/final_boss 概率为遗留值，不要恢复。
8. **存档字段全部防御式读取**——新增字段时同步实现"缺失/非法回退"，旧档兼容靠它。
